# ❓ Как устроен HashMap внутри в Java 8+?

### ⚡ Краткий ответ (TL;DR для повторения за 30–60 сек)
- Базируется на массиве бакетов `Node<K,V>[] table`.
- Индекс бакета вычисляется как `(n - 1) & hash(key)`.
- **Коллизии** разрешаются методом цепочек. Если в одном бакете накапливается $\ge 8$ элементов (`TREEIFY_THRESHOLD`) и размер всей таблицы $\ge 64$ (`MIN_TREEIFY_CAPACITY`), связный список преобразуется в **красно-черное самобалансирующееся дерево** (`TreeNode`), ускоряя поиск с $O(N)$ до $O(\log N)$.
- При уменьшении узлов до 6 (`UNTREEIFY_THRESHOLD`) дерево обратно преобразуется в список.
- По умолчанию: `initialCapacity = 16`, `loadFactor = 0.75`. При превышении `capacity * loadFactor` массив удваивается (rehashing).

---

### 📖 Развернутый ответ

#### 1. Структура данных и поля
Внутри `HashMap` объявлен массив корзин (бакетов):
```java
transient Node<K,V>[] table;
```
Каждый элемент `Node<K,V>` содержит:
- `final int hash` — предрассчитанный хеш ключа.
- `final K key` — сам ключ.
- `V value` — значение.
- `Node<K,V> next` — ссылка на следующий узел (в случае связного списка).

#### 2. Функция хеширования (Хеш-функция)
Для равномерного распределения по бакетам применяется смешивающая функция:
```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```
Старшие биты сдвигаются вправо на 16 и выполняют XOR с младшими битами. Это предотвращает коллизии, когда у объектов различаются только старшие биты.

#### 3. Алгоритм вставки (`put(K, V)`)
1. Если `table == null` или `table.length == 0` — вызывается `resize()`.
2. Вычисляется индекс корзины: `i = (n - 1) & hash`.
3. Если бакет пуст (`table[i] == null`) — создается новый `Node` и помещается в бакет.
4. Если бакет занят (коллизия):
   - Если ключ совпадает (`hash` совпадает И (`==` или `.equals()`)): значение перезаписывается.
   - Если узел является экземпляром `TreeNode` — вставка в красно-черное дерево.
   - Если это связный список — итерируемся до конца (или до нахождения ключа). Если элементов стало $\ge 8$, вызывается `treeifyBin()` (превращение в дерево, если `table.length >= 64`, иначе просто `resize()`).
5. Если количество элементов превысило `threshold = capacity * loadFactor`, происходит расширение таблицы (`resize()` удваивает `capacity`).

### 🔥 Каверзные вопросы на собеседовании

1. *Почему `null` разрешен в качестве ключа и куда он попадает?*
   - **Ответ**: `hash(null)` равен 0. Он всегда попадает в нулевой бакет (`table[0]`). В `ConcurrentHashMap` и `Hashtable` ключ `null` запрещен.

2. *Что произойдет, если использовать изменяемый (mutable) объект в качестве ключа?*
   - **Ответ**: Если после добавления в `HashMap` изменить состояние объекта так, что изменится его `hashCode()`, метод `get(key)` уже не сможет найти значение (он пойдет искать в другой бакет по новому хешу). Это классическая утечка памяти.

3. *Почему размер массива `table` всегда степень двойки ($2^N$)?*
   - **Ответ**: Чтобы заменить медленную операцию деления с остатком `hash % n` на быструю побитовую операцию `hash & (n - 1)`. Это работает строго при $n = 2^k$.
