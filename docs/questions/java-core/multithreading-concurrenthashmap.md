# ❓ Внутреннее устройство ConcurrentHashMap в Java 8+

### ⚡ Краткий ответ (TL;DR для повторения за 30–60 сек)
- В Java 7 использовался **Segment Locking** (массив `Segment` на базе `ReentrantLock`, по умолчанию 16 сегментов).
- В **Java 8+ сегменты удалены**. Блокировка происходит на уровне **отдельного бакета (первого узла корзины)** через встроенный монитор `synchronized (node)`.
- Если бакет пуст — вставка нового узла выполняется **без блокировок** с помощью неблокирующего алгоритма **CAS (Compare-And-Swap)** через `Unsafe`/`VarHandle`.
- Операции чтения (`get()`) выполняются **полностью без блокировок** благодаря объявлению полей `val` и `next` как `volatile`.
- Значения `null` для ключей и значений **запрещены**.

### 📖 Развернутый ответ

#### 1. Сравнение подходов
| Характеристика | `Hashtable` / `synchronizedMap` | `ConcurrentHashMap` (Java 7) | `ConcurrentHashMap` (Java 8+) |
| :--- | :--- | :--- | :--- |
| **Уровень блокировки** | Вся коллекция целиком (1 общий монитор) | Массив из 16 `Segment` (каждый со своим локом) | Отдельный первый узел бакета (`synchronized(node)`) |
| **Параллельная запись** | 1 поток на всю мапу | До 16 потоков параллельно | Потоки могут одновременно писать в разные бакеты |
| **Операция чтения `get`**| Блокирует всю мапу | Без блокировки (volatile) | Без блокировки (volatile node values) |
| **Разрешен ли `null`?** | Нет | Нет | Нет |

#### 2. Как работает `putVal(key, value)` в Java 8+:
1. Проверка: если `key == null` или `value == null` — немедленно бросает `NullPointerException`.
2. Вычисляется спред-хеш ключа: `(h ^ (h >>> 16)) & HASH_BITS`.
3. В бесконечном цикле (`for (Node<K,V>[] tab = table;;)`):
   - Если таблица еще не инициализирована — инициализация через CAS (`initTable()`).
   - Если бакет по индексу `(n - 1) & hash` **пустой** — попытка вставить новый `Node` через **CAS** (`casTabAt`). Если CAS успешен — выходим без каких-либо блокировок!
   - Если в бакете обнаружен служебный узел перехеширования `MOVED` (хеш равен `-1`) — текущий поток помогает расширению таблицы (`helpTransfer()`).
   - Иначе (коллизия в существующем бакете) — берется `synchronized` на **первый узел корзины** `synchronized (f)`. Внутри синхронизированного блока список обходится или вставляется в красно-черное дерево.
4. Вызывается `addCount()`, который параллельно и потокобезопасно обновляет счетчик размера через аналог `LongAdder` (`CounterCell[]`).

### 🔥 Каверзные вопросы на собеседовании

1. *Почему `null` запрещен в `ConcurrentHashMap`, но разрешен в `HashMap`?*
   - **Ответ**: В многопоточной среде невозможно различить: значение `null` отсутствует или ключ ассоциирован со значением `null`. Метод `containsKey()` между вызовами `get()` может вернуть устаревший результат из-за гонки потоков (Race Condition). Создатель Doug Lea намеренно запретил `null`.

2. *Является ли составная операция `if (!map.containsKey(k)) map.put(k, v);` атомарной?*
   - **Ответ**: Нет, между проверкой и вставкой другой поток может изменить значение. Для атомарных составных операций нужно использовать методы `putIfAbsent()`, `computeIfAbsent()`, `compute()`, `merge()`.

3. *Как вычисляетс�� `size()` без блокировки всей таблицы?*
   - **Ответ**: Используется счетчик на базе `CounterCell[]` (аналог `LongAdder`). Потоки инкрементируют свои ячейки через CAS, минимизируя конкуренцию за одну переменную. Метод `size()` просто суммирует значения ячеек.
