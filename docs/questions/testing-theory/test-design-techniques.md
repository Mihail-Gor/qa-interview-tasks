# ❓ Техники тест-дизайна в автоматизации тестирования

### ⚡ Краткий ответ (TL;DR для повторения за 30–60 сек)
- **Эквивалентное разбиение (Equivalence Partitioning)**: разбиение диапазона входных данных на классы, где система ведет себя одинаково. Достаточно проверить 1 значение из каждого класса (валидные и невалидные).
- **Анализ граничных значений (Boundary Value Analysis)**: проверка границ классов эквивалентности (граница, граница - 1, граница + 1, либо 2-точечный подход). Большинство багов сосредоточено на границах.
- **Попарное тестирование (Pairwise Testing)**: комбинаторная техника (все пары значений параметров). Сокращает матрицу комбинаций в разы при сохранении высокого покрытия.
- **Таблица решений (Decision Table)**: для тестирования сложной бизнес-логики с комбинациями условий и действий.
- **Диаграмма переходов состояний (State Transition)**: тестирование объектов с жизненным циклом (заказ: Created -> Paid -> Shipped -> Delivered).

### 📖 Развернутый ответ и применение в коде

#### 1. Как применять техники в параметризованных тестах (JUnit 5)
При автоматизации мы объединяем граничные значения и классы эквивалентности в `@ParameterizedTest`:

```java
// Тестирование возраста студента [18..65]
@ParameterizedTest(name = "Валидация возраста: {0} -> валиден: {1}")
@CsvSource({
    "17, false", // Граница - 1 (невалидно)
    "18, true",  // Нижняя граница (валидно)
    "19, true",  // Внутри диапазона (валидно)
    "35, true",  // Эквивалентный класс
    "65, true",  // Верхняя граница (валидно)
    "66, false", // Граница + 1 (невалидно)
    "-1, false", // Отрицательное число
    "999, false" // Экстремальное значение
})
void testStudentAgeValidation(int age, boolean expectedValid) {
    assertThat(Validator.isValidAge(age)).isEqualTo(expectedValid);
}
```

### 🔥 Каверзные вопросы на собеседовании

1. *В чем разница между 2-точечным и 3-точечным граничным анализом?*
   - **2-точечный**: проверяет саму границу и точку за границей (например, для `>= 18`: точки `18` и `17`).
   - **3-точечный**: проверяет точку до границы, саму границу и точку после границы (`17`, `18`, `19`).

2. *Когда применять Pairwise, а когда полный перебор (Combinatorial)?*
   - Pairwise применяется при большом количестве параметров (например, фильтры в интернет-магазине из 10 селектов), где полный перебор дал бы $3^{10} = 59049$ тестов. Pairwise сокращает это до ~30-50 тестов, находя до 90% дефектов взаимодействия.
