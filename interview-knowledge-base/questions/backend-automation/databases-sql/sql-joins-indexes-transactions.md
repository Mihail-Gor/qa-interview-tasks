# ❓ SQL: JOINs, Индексы, Транзакции и ACID

### ⚡ Краткий ответ (TL;DR для повторения за 30–60 сек)
- **JOINs**: `INNER` (пересечение), `LEFT` (все из левой + совпадения справа), `RIGHT`, `FULL OUTER`, `CROSS` (декартово произведение).
- **ACID**: **A**tomicity (все или ничего), **C**onsistency (целостность данных/констрейнты), **I**solation (независимость параллельных транзакций), **D**urability (надежность/сохранение на диск).
- **Индексы**: B-Tree (по умолчанию, сбалансированное дерево, $O(\log N)$ на поиск/диапазоны), Hash (только точное равенство $O(1)$), GIN/GiST. Индексы ускоряют `SELECT`, но замедляют `INSERT`/`UPDATE`/`DELETE`.
- **Уровни изоляции**:
  1. *Read Uncommitted* (возможен Dirty Read).
  2. *Read Committed* (защищает от Dirty Read; дефолт в PostgreSQL/Oracle).
  3. *Repeatable Read* (защищает от Non-Repeatable Read; дефолт в MySQL InnoDB).
  4. *Serializable* (полная изоляция, защита от Phantom Read, максимальные блокировки).

### 📖 Развернутый ответ

#### 1. Феномены параллельного чтения
- **Грязное чтение (Dirty Read)**: Транзакция A читает незакоммиченные данные транзакции B. Если B сделает `ROLLBACK`, данные окажутся ложными.
- **Неповторяющееся чтение (Non-Repeatable Read)**: Транзакция A дважды выполняет один и тот же `SELECT` по строке и получает **разные значения полей**, потому что между запросами транзакция B обновила (`UPDATE`) строку и сделала `COMMIT`.
- **Фантомное чтение (Phantom Read)**: Транзакция A дважды выполняет `SELECT` с условием (`WHERE age > 18`) и во второй раз получает **новые строки**, добавленные транзакцией B (`INSERT`/`DELETE` + `COMMIT`).

#### 2. Матрица уровней изоляции SQL
| Уровень изоляции | Dirty Read | Non-Repeatable Read | Phantom Read |
| :--- | :---: | :---: | :---: |
| **Read Uncommitted** | ❌ (Возможен) | ❌ (Возможен) | ❌ (Возможен) |
| **Read Committed**   | ✅ (Защищен)  | ❌ (Возможен) | ❌ (Возможен) |
| **Repeatable Read**  | ✅ (Защищен)  | ✅ (Защищен)  | ❌ / ✅ (Защищен в InnoDB через Next-Key Lock) |
| **Serializable**     | ✅ (Защищен)  | ✅ (Защищен)  | ✅ (Защищен)  |

### 🔥 Каверзные вопросы на собеседовании

1. *В чем разница между `WHERE` и `HAVING`?*
   - `WHERE` фильтрует строки **до** группировки (`GROUP BY`) и не может использовать агрегатные функции (`COUNT`, `SUM`, `AVG`).
   - `HAVING` фильтрует группы строк **после** группировки и работает с агрегатными функциями.

2. *В чем разница между `TRUNCATE`, `DROP` и `DELETE`?*
   - `DELETE` — DML-команда, удаляет строки построчно, пишет в транзакционный лог, поддерживает `WHERE`, можно откатить (`ROLLBACK`), срабатывают триггеры.
   - `TRUNCATE` — DDL-команда, быстро освобождает страницы таблицы, сбрасывает автоинкремент, не построчная, триггеры не срабатывают.
   - `DROP` — DDL-команда, удаляет таблицу и ее схему целиком.

3. *Что такое Clustered vs Non-Clustered Index?*
   - **Clustered Index**: определяет физический порядок хранения данных в таблице (на таблицу может быть только один, обычно по Primary Key).
   - **Non-Clustered Index**: отдельная структура со ссылками на строки таблицы (на таблицу может быть много).
