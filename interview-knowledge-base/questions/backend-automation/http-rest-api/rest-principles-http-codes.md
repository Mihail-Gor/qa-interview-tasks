# ❓ Принципы REST, HTTP методы и идемпотентность

### ⚡ Краткий ответ (TL;DR для повторения за 30–60 сек)
- **REST (Representational State Transfer)** — архитектурный стиль взаимодействия систем через Stateless протокол (HTTP).
- **Идемпотентность**: повторный вызов запроса с теми же параметрами дает тот же результат на сервере (`GET`, `PUT`, `DELETE`, `HEAD`, `OPTIONS` — идемпотентны; `POST`, `PATCH` — обычно НЕ идемпотентны).
- **Безопасность (Safe methods)**: методы, которые НЕ изменяют состояние ресурса (`GET`, `HEAD`, `OPTIONS`).
- **Коды ответов**:
  - `2xx` — Успех (`200 OK`, `201 Created`, `204 No Content`).
  - `3xx` — Перенаправление (`301 Moved Permanently`, `304 Not Modified`).
  - `4xx` — Ошибка клиента (`400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict`, `422 Unprocessable`).
  - `5xx` — Ошибка сервера (`500 Internal Error`, `502 Bad Gateway`, `503 Service Unavailable`, `504 Gateway Timeout`).

### 📖 Развернутый ответ

#### 1. Сравнение HTTP методов
| Метод | Назначение | Идемпотентный? | Безопасный? | Тело запроса? |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | Получение ресурса | ✅ Да | ✅ Да | ❌ Нет |
| `POST` | Создание нового ресурса или выполнение действия | ❌ Нет | ❌ Нет | ✅ Да |
| `PUT` | Полная замена (или создание по известному URI) | ✅ Да | ❌ Нет | ✅ Да |
| `PATCH` | Частичное обновление полей ресурса | ❌ Нет (обычно) | ❌ Нет | ✅ Да |
| `DELETE` | Удаление ресурса | ✅ Да | ❌ Нет | Редко |

#### 2. Шесть ограничений (Constraints) REST
1. **Client-Server Architecture**: разделение интерфейса пользователя и хранения данных.
2. **Stateless**: сервер не хранит состояние сессии клиента между запросами; каждый запрос самодостаточен.
3. **Cacheable**: ответы должны явно помечаться как кэшируемые или некэшируемые (`Cache-Control`).
4. **Uniform Interface**: единый интерфейс (URI для ресурсов, манипуляция через представления, самоописываемые сообщения, HATEOAS).
5. **Layered System**: клиент не знает, общается ли он напрямую с сервером или с промежуточными прокси/балансировщиками.
6. **Code on Demand (опционально)**: возможность передавать исполняемый код (например, JavaScript).

### 🔥 Каверзные вопросы на собеседовании

1. *В чем разница между `401 Unauthorized` и `403 Forbidden`?*
   - **401 Unauthorized**: Пользователь **не аутентифицирован** (не передал токен или токен невалиден / истек). Требуется войти в систему.
   - **403 Forbidden**: Пользователь **успешно аутентифицирован**, но у него **недостаточно прав** (ролей/permission) для доступа к данному ресурсу.

2. *В чем разница между `PUT` и `PATCH`?*
   - `PUT` ожидает **полное тело объекта** и перезаписывает его целиком (неуказанные поля могут сброситься в `null`).
   - `PATCH` отправляет только **изменившиеся поля** (delta/diff).

3. *Почему `DELETE` считается идемпотентным, если второй вызов вернет `404 Not Found`?*
   - **Ответ**: Идемпотентность оценивается по **состоянию системы на сервере**, а не по возвращаемому коду ответа. После первого `DELETE` ресурс удален. После второго `DELETE` ресурс по-прежнему удален — состояние сервера не изменилось.
