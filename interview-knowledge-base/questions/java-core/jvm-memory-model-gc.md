# ❓ Память JVM и сборщики мусора (Garbage Collectors)

### ⚡ Краткий ответ (TL;DR для повторения за 30–60 сек)
- **Области памяти**:
  - **Stack** (на каждый поток): вызовы методов, примитивные локальные переменные, ссылки на объекты.
  - **Heap (Куча)** (общий на всю JVM): все объекты (`new`), массивы. Делится на **Young Gen** (Eden, Survivor S0/S1) и **Old (Tenured) Gen**.
  - **Metaspace** (Native memory): метаданные классов, статические переменные классов (в Java 8 заменил PermGen).
- **GC алгоритмы**:
  - **Minor GC**: очистка Young Gen (быстрый копирующий алгоритм).
  - **Major / Full GC**: очистка Old Gen + Metaspace (Stop-The-World паузы).
  - Популярные GC: **G1 GC** (по умолчанию с Java 9, регионный, предсказуемые паузы), **ZGC / Shenandoah** (паузы < 1ms для больших Heap).

---

### 📖 Развернутый ответ

#### 1. Жизненный цикл объекта в Heap
1. Новый объект создается в области **Eden**.
2. При заполнении Eden запускается **Minor GC**: живые объекты копируются в **Survivor 0 (S0)**.
3. При следующих Minor GC объекты перемещаются между S0 и S1, а их счетчик возраста (age/tenuring threshold) инкрементируется.
4. Когда возраст достигает порога (по умолчанию 15), объект переходит в **Old Generation** (Tenured).
5. Большие объекты (крупные массивы) могут аллоцироваться сразу в Old Gen (Humongous objects в G1).

#### 2. Виды OutOfMemoryError
- `java.lang.OutOfMemoryError: Java heap space` — переполнение кучи (утечка памяти, например, незакрытые ресурсы или бесконечно растущая статическая коллекция).
- `java.lang.OutOfMemoryError: Metaspace` — переполнение памяти классов (динамическая генерация классов, CGLIB-прокси, многократная перезагрузка classloader).
- `java.lang.StackOverflowError` — переполнение стека потока (бесконечная рекурсия).

### 🔥 Каверзные вопросы на собеседовании

1. *Что такое утечка памяти (Memory Leak) в Java, если есть GC?*
   - **Ответ**: Утечка в Java — это ситуация, когда неиспользуемый объект остается достижимым из **GC Roots** (например, через `static` коллекцию, незакрытый `ThreadLocal`, незарегистрированный слушатель событий). GC не может его удалить.

2. *В чем разница между `Strong`, `Soft`, `Weak` и `Phantom` ссылками?*
   - **Strong**: обычная ссылка, никогда не собирается GC.
   - **Soft**: собирается только при нехватке памяти (отлично для кэшей).
   - **Weak**: собирается при первом же проходе GC (используется в `WeakHashMap`).
   - **Phantom**: используется для отслеживания момента очистки объекта и очистки native-памяти.
